# Runtime Support Files

> Read on demand before changing page relationships, graph edges/citations, the catalog, or weekly logs. `wiki/` denotes the configured external wiki root.

## Link Syntax

All internal links use Obsidian wikilinks:

```markdown
[[slug]]                    ← link to any page in this wiki
[[lora-low-rank-adaptation]] ← links to papers/lora-low-rank-adaptation.md
[[flash-attention]]          ← links to concepts/flash-attention.md
```

**Naming convention**: non-paper pages are lowercase, hyphen-separated, with no spaces. Paper pages use `citationKey` or `author_year_veryshorttitle`, so they may contain mixed case, underscores, dots, plus signs, or hyphens.

## Cross-Reference Rules

When writing a forward link, **always write the reverse link simultaneously**:

| Forward action | Required reverse action |
|----------------|------------------------|
| papers/A writes `Related: [[concept-B]]` | concepts/B appends A to `key_papers` |
| papers/A writes `[[researcher-C]]` | people/C appends A to `Key papers` |
| papers/A writes `supports: [[claim-D]]` | claims/D appends `{source: A, type: supports}` to `evidence` |
| topics/T writes `key_people: [[person-D]]` | people/D appends T to `Research areas` |
| concepts/K writes `key_papers: [[paper-E]]` | papers/E appends K to `Related` |
| concepts/K writes part_of `[[topic-F]]` | topics/F appends K to overview paragraph |
| ideas/I writes `origin_gaps: [[claim-C]]` | claims/C appends I to `## Linked ideas` |
| experiments/E writes `target_claim: [[claim-C]]` | claims/C appends `{source: E, type: tested_by}` to `evidence` |
| claims/C writes `source_papers: [[paper-P]]` | papers/P appends C to `## Related` |
| any page links to `[[foundation-X]]` | **no reverse link** — foundations are terminal: they receive inward links from papers/concepts/etc. but never write `key_papers` or any back-reference field |

Experiment records live under `experiment_root`; reports live under `output_root`.
The `experiments/E` notation above and in graph endpoints is a logical identity,
resolved by `tools/_content.py`, rather than a child path of `wiki_root`.
Slug wikilinks and claim evidence sources remain unchanged by relocation.

## Graph Rules

- `graph/` is auto-generated; do not edit it manually
- core derived files are `edges.jsonl`, `citations.jsonl`, `context_brief.md`, and `open_questions.md`
- semantic edge types include paper-paper (`same_problem_as`, `similar_method_to`, `complementary_to`, `builds_on`, `compares_against`, `improves_on`, `challenges`, `surveys`), paper-concept (`introduces_concept`, `uses_concept`, `extends_concept`, `critiques_concept`), and existing claim/experiment/provenance types (`supports`, `contradicts`, `tested_by`, `invalidates`, `addresses_gap`, `derived_from`, `inspired_by`)
- `/ingest` paper-paper and paper-concept semantic edges must include `confidence: high|medium|low`
- symmetric paper-paper edges are stored once with sorted endpoints and `symmetric: true`
- bibliographic citations live in `citations.jsonl` as `type: cites`
- use `tools/research_wiki.py add-edge`, `add-citation`, `rebuild-context-brief`, and `rebuild-open-questions`

To correct the evidence text of an existing semantic edge, use
`research_wiki.py set-edge-evidence <wiki_root> --from <id> --to <id> --type <type>`
with exactly one of `--evidence "..."` or `--evidence-file <utf8-file>`.
The command requires a unique existing edge (including canonical symmetric
matching), changes only `evidence`, and preserves confidence, dates, custom
metadata, and unrelated rows. Missing/duplicate targets, invalid JSON, and empty
evidence are rejected without writing. `--expected-evidence "..."` optionally
guards against replacing a different prior value. Updates use an atomic file
replacement; this does not provide locking against other graph writers.
Repeated updates to the same text are no-ops. Rebuild derived context after
actual changes and append the authorized audit log through `log`.

## Graph Files

| File | Content | Generated by |
|------|---------|-------------|
| `edges.jsonl` | semantic relationships: paper-paper, paper-concept, claim/experiment/idea/provenance edges | `uv run python -X utf8 tools/research_wiki.py add-edge` |
| `citations.jsonl` | bibliographic paper citations (`type: cites`) | `uv run python -X utf8 tools/research_wiki.py add-citation` |
| `context_brief.md` | compressed context: claims + gaps + failed ideas + papers + edges (≤8000 chars) | `uv run python -X utf8 tools/research_wiki.py rebuild-context-brief` |
| `open_questions.md` | open questions: under-supported claims + open questions from papers/topics | `uv run python -X utf8 tools/research_wiki.py rebuild-open-questions` |

Semantic edge format: `{"from": "node_id", "to": "node_id", "type": "edge_type", "evidence": "...", "confidence": "high|medium|low", "date": "..."}`

Citation format: `{"from": "papers/citing", "to": "papers/cited", "type": "cites", "source": "literature_api|parsed_bib|manual", "date": "..."}`

## index.md Format

`rebuild-index` scans the independent experiment/output roots as well as wiki
entities. Each experiment/output entry includes its path relative to `wiki_root`;
custom directory names and locations are supported. Output entries are document
navigation, not new claim evidence. Existing `outputs/<slug>` provenance edges remain valid.


Entity scanners exclude filenames containing `NSConflict` (case-insensitive),
including numbered variants. They report skipped paths on stderr; `lint.py`
also reports `sync-conflict` findings. Copies without a canonical counterpart
are still excluded and must be reconciled explicitly. This applies to index,
query/statistics, grounding, discovery, classification, promotion, bibliographic
backfill, source-quality page scans, and batch re-OCR page discovery.

After reviewing and merging duplicate page identities, use
`research_wiki.py remap-graph-nodes <wiki_root> --mapping <json-file>` to map
old node ids to existing canonical pages in `edges.jsonl` and `citations.jsonl`.
The JSON file is a nonempty object of old-to-new node ids of the same entity
kind; chained mappings and missing destinations are rejected. The tool checks
both files before writing and preserves unrelated rows and custom metadata.
Collisions with different metadata (other than date) are rejected for explicit
reconciliation; equivalent rows keep the existing canonical record. Each file
is replaced atomically, without a transaction across files or writer locking.
Back up first and rebuild the derived context and index after reconciliation.

papers:

## log/ Format

Logs are written to `wiki/log/{yyyy-mm-wN}.md`, where `wN` is the week-of-month bucket: days 1–7 are `w1`, days 8–14 are `w2`, and so on.

Each weekly log file uses `# log` as the top-level heading and skill names as second-level headings. Standard format:

```markdown
# log

## ingest-light
[YYYY-MM-DD] added something

## ingest
[YYYY-MM-DD] added something
```

Append log entries only through the tool:

```shell
uv run python -X utf8 tools/research_wiki.py log '@configured' "ingest-light | added something"
```

Write logs only after actual repairs/content writes or an explicitly requested report archive, as authorized by the skill. Default read-only checks/audits and dry-run/no-write operations do not create logs or maintenance files.
