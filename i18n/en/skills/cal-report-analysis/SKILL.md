# /cal-report-analysis

> Generate browsable calculation report pages with `tools/cal_data_index.py`, then write a grounded analysis from those pages and their linked source artifacts.
> Use this for calculation output folders, experiment result dumps, metric tables, JSONL samples, logs, configs, and plots stored under the configured raw root.

## Trigger

User manual: `/cal-report-analysis [scope] [...]`

Use this skill when the user asks to analyze calculation outputs, compare calculation runs, summarize local metric/result artifacts, or produce a report from files under configured `raw_root/cal_data` or another calculation data directory.

## Inputs

- `scope` optional: run name, report slug, data subdirectory, or analysis question. If omitted, analyze all discovered runs.
- `--data-dir` optional, default `cal_data`: data directory containing calculation output files. **Path is relative to `--data-root`** (default: `raw_root` from `config/paths.json`). Example: with raw_root at `/path/to/raw`, `--data-dir cal_data/Ni_Ca-like` resolves to `/path/to/raw/cal_data/Ni_Ca-like`.
- `--data-root` optional, default: `raw_root`. Root path for `--data-dir`. Use `@configured` to point at the wiki root instead.
- `--report-dir` optional, default `experiments/cal_reports`: wiki-relative directory where the indexer writes report pages. Always relative to wiki_root.
- `--table-rows` optional, default `8`: preview rows per CSV/TSV file.
- `--text-lines` optional, default `20`: preview lines per JSONL/text/log/config file.
- `--no-write` optional: skip archiving and return the final analysis only in the response.

**Data location**: By default, calculation data should live under `raw/cal_data/`. If the tool prints "No calculation data found", place your CSV/JSONL files there. To analyze data stored under the wiki root instead, pass `--data-root @configured`.

## Outputs

- `experiments/cal_reports/index.md` and one generated report page per calculation run.
- A concise analysis report in the response.
- By default: `wiki/outputs/cal-report-analysis-{slug}-{date}.md` plus a log entry.
- With `--no-write`: no archived analysis artifact or log entry.

## Wiki Interaction

### Reads
- `cal_data/` under configured `raw_root` by default, or the user-provided `--data-root` + `--data-dir`.
- `experiments/cal_reports/index.md` and selected run report pages generated by the indexer.
- Linked source files from those run pages when a conclusion depends on exact values, full logs, or plots beyond the preview.
- Existing `wiki/claims/`, `wiki/experiments/`, `wiki/ideas/`, and `wiki/papers/` only when the user asks to connect the analysis to prior wiki knowledge.

### Writes
- Generated calculation report pages under `--report-dir`; these pages are regenerated by the indexer and are not a durable place for hand-written notes.
- By default: one analysis artifact under `wiki/outputs/`.
- By default: append a weekly log entry through `tools/research_wiki.py log`.
- With `--no-write`: do not write the analysis artifact or log entry.

### Graph edges created
- None by default.
- If the archived analysis cites existing wiki pages and derived provenance is useful, add `derived_from` edges with `tools/research_wiki.py add-edge`. Do not edit `wiki/graph/` manually.

## Workflow

Run commands from the llm-wiki repository root. Use runtime path aliases rather than hard-coding an absolute wiki path.

### Step 1: Generate or Refresh Calculation Report Pages

Run the indexer before analysis unless the user explicitly asks to use existing report pages unchanged:

```shell
# Default: data under raw_root (raw/cal_data)
uv run python -X utf8 tools/cal_data_index.py @configured --data-dir cal_data/Ni_Ca-like --report-dir experiments/cal_reports

# When data lives under wiki_root instead
uv run python -X utf8 tools/cal_data_index.py @configured --data-root @configured --data-dir temp/cal_data/Ni_Ca-like --report-dir experiments/cal_reports
```

Adjust flags only when the user supplied them or the requested scope requires a different data/report directory. The tool discovers direct files and run subdirectories, writes one page per run, embeds CSV/TSV previews, JSONL/text snippets, image links, file sizes, and item counts.

If the command reports zero runs, stop and say no calculation data was found under the resolved data directory. Do not fabricate an analysis.

### Step 2: Select the Evidence Set

**HARD RULE — scope is user-defined, not directory-defined.** When the user names specific files (e.g. "analyze even1_cc1as2_rmcdhf.csv, even1_cc2as2_rmcdhf.csv"), limit analysis to **exactly those files**. Do NOT read or analyze sibling files in the same directory, even if they appear related or provide useful context. Only expand beyond the named files when the user explicitly asks for a full-directory analysis.

1. Read `experiments/cal_reports/index.md`.
2. Select report pages by the user scope:
   - explicit run/report slug: read that page.
   - data subdirectory: read pages whose source path matches it.
   - comparison request: read all matching run pages.
   - omitted scope: read all run pages, but summarize selection if there are many.
   - **named files**: read only the files the user listed. Do not add unlisted files from the same directory.
3. For each selected run, inspect:
   - file inventory and file types.
   - row/item counts.
   - metric tables.
   - config/log snippets.
   - plots and image links.
4. Open linked source files when previews are insufficient, especially for final metric values, full error traces, configuration differences, or plots that need visual inspection.

### Step 3: Analyze

Ground every claim in generated report pages or linked source files. Prefer exact filenames and metric names over vague statements.

Answer these questions when applicable:

- What runs were analyzed, and which files support the analysis?
- What are the primary metrics, baselines, variants, or settings?
- Which values changed materially across runs?
- Which rows, samples, logs, or plots indicate anomalies or failure modes?
- Which configuration differences plausibly explain the results?
- What conclusions are directly supported?
- What remains unknown because the data, metadata, or preview is insufficient?

Do not infer causality from correlation alone. If a plot or table suggests a trend but lacks metadata, label it as an observed association.

### Step 4: Write the Analysis Report

Use this structure unless the user asks for another format:

```markdown
# Calculation Report Analysis: {scope}

## Scope
- Data directory:
- Generated report index:
- Runs analyzed:
- Source files checked:

## Executive Summary

## Key Results

## Run-by-Run Notes

## Cross-Run Comparison

## Anomalies and Failure Signals

## Interpretation

## Limits and Unknowns

## Recommended Next Checks
```

Keep the analysis concrete:

- Include table names, column names, run names, and linked report/source paths.
- Separate observations from interpretation.
- Preserve uncertainty when metadata is missing.
- Avoid generic prose that could apply to any experiment.

### Step 5: Archive by Default

Skip this step only when the user supplied `--no-write`.

1. Generate a slug from the scope:

   ```shell
   uv run python -X utf8 tools/research_wiki.py slug "cal report analysis {scope}"
   ```

2. Resolve the configured wiki root before direct file writes:

   ```shell
   uv run python -X utf8 tools/resolve_path_alias.py @configured
   ```

3. Create `outputs/cal-report-analysis-{slug}-{date}.md` with frontmatter:

   ```yaml
   ---
   title: "Calculation Report Analysis: {scope}"
   slug: "cal-report-analysis-{slug}-{date}"
   artifact_type: cal_report_analysis
   date_created: YYYY-MM-DD
   data_root: "{data-root}"
   data_dir: "{data-dir}"
   report_index: "experiments/cal_reports/index.md"
   source_reports:
     - "experiments/cal_reports/{run}.md"
   source_files:
     - "{data-dir}/{run}/{file}"
   ---
   ```

4. Add the report body after frontmatter.
5. If `wiki/index.md` lists outputs, add the new output entry there.
6. Append the log entry through the tool:

   ```shell
   uv run python -X utf8 tools/research_wiki.py log @configured "cal-report-analysis | {scope} | runs: {N} | output: outputs/{slug}.md"
   ```

7. Add graph edges only through `tools/research_wiki.py add-edge` when the analysis derives from existing wiki pages, not merely from local calculation files.

## Constraints

- Treat generated report pages as an evidence index, not as proof by themselves; read linked source files for decisive numerical or diagnostic claims.
- Treat generated report pages as disposable indexer output. Do not add persistent hand-written notes to those pages; put durable interpretation in the archived analysis artifact or in a separate user-authored Markdown file.
- Do not edit files in `wiki/graph/` manually.
- Do not convert report pages into normal `experiments/` pages unless the user explicitly requests crystallization into experiment entities.
- Do not overwrite user-owned calculation data under configured `raw_root/cal_data/`.
- If a file is binary or unsupported, mention it in the inventory but do not infer contents from the filename alone.
- **File scope is user-defined.** Only analyze files the user explicitly names. Never read or include sibling files from the same directory unless the user asks for a full-directory analysis. If the user names 3 CSV files, analyze exactly those 3 — no more.
- Archive by default. Only skip `wiki/outputs/` and log writes when the user supplied `--no-write`.

## Dependencies

### Tools
- `uv run python -X utf8 tools/cal_data_index.py @configured ...` - generate calculation report pages.
- `uv run python -X utf8 tools/research_wiki.py slug ...` - generate archive slug.
- `uv run python -X utf8 tools/research_wiki.py log @configured ...` - append log entry.
- `uv run python -X utf8 tools/research_wiki.py add-edge ...` - optional derived provenance edges.
- `uv run python -X utf8 tools/resolve_path_alias.py @configured` - resolve the active wiki root before direct writes.
